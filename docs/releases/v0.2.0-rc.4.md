# FORGE v0.2.0-rc.4

Date: 2026-08-21
Status: candidate prepared for unsigned bounded tester evaluation; publication
requires the protected CI and tag-bound release gates to pass.

## What changed since rc.3

- Workbench navigation now uses human goals: Inicio, Trabajo, Memoria and
  Recuperación.
- Inicio derives one project-scoped recommended next action from the existing
  catalog instead of presenting a static setup prompt.
- Creation actions appear only in their relevant context and dashboard metrics
  navigate directly to the corresponding workspace.
- Operational flow is ordered task → execution → agent, while operation errors
  remain visible independently from semantic-search results.
- Mobile navigation uses a stable 2x2 layout validated at 390 x 844 pixels.

There are no database migrations or breaking Gateway/MCP contract changes
between rc.3 and rc.4.

## Compatibility

- PostgreSQL 14 or newer.
- pgvector 0.8.2 for vector migrations and semantic retrieval.
- Windows x64 for the packaged Workbench candidate.
- Node.js 20+ and npm 10+ for the guided source bootstrap.
- LM Studio remains optional except for semantic search.

## Tester path

Follow [TESTING-RC.md](../TESTING-RC.md). Existing rc.3 users should perform the
documented credential-preserving update check. Testers must verify the
published SHA-256 manifest and must not attach credentials, DPAPI files,
database dumps or recovery material to issue reports.

## Known limitations

- This candidate remains unsigned while SignPath Foundation onboarding is
  pending. Windows may identify the publisher as unknown or display SmartScreen.
- PostgreSQL and the FORGE schema are prerequisites for the standalone
  Workbench ZIP; the source archive contains the guided full bootstrap.
- Automatic failover, multi-node high availability and remote multi-user
  Workbench hosting remain outside this candidate.
- Fast semantic top-1 quality remains below the precision reranker gate;
  precision mode is optional and requires its documented local model.
- TencentDB compatibility remains unverified on a live provider instance.

## Required validation before publication

- Full monorepo build/test and zero known production vulnerabilities.
- PostgreSQL 14 schema restart plus Gateway/MCP continuity.
- Clean Windows bootstrap, DPAPI Workbench startup, resume and safe rollback.
- Update from the exact public rc.3 ZIP with byte-identical configuration and
  DPAPI preservation.
- Desktop and 390 x 844 Workbench navigation without overflow or console errors.
- Tag-bound source and Windows archives with matching internal and outer
  SHA-256 manifests.
- GitHub provenance attestations for both public archives.

## Rollback

Withdraw rc.4 and direct testers to rc.3. Preserve the database and shared user
configuration; never reverse database migrations with destructive ad-hoc SQL.
Cross-project visibility, persistence loss, unusable navigation,
mixed-version installation, configuration/DPAPI loss, checksum mismatch,
non-loopback binding or credential exposure are immediate withdrawal triggers.
