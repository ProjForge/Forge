# FORGE v0.2.0-rc.1

Date: 2026-08-14  
Status: unsigned technical prerelease for evaluation and SignPath Foundation
onboarding; not a signed general-user release.

## What this candidate establishes

- Core Complete relational, agent, human, semantic and recovery workflows.
- PostgreSQL 14+ compatibility enforced in CI and validated locally on
  PostgreSQL 18.3.
- Resumable Windows bootstrap with least-privilege runtime roles.
- Loopback-only Workbench with DPAPI-protected database credentials.
- Release-verifiable Windows packaging with source commit metadata, SHA-256
  manifests, Apache-2.0 project notices and bundled third-party licenses.
- Optional Authenticode signing with mandatory RFC 3161 timestamping and
  post-signature verification.

## Compatibility

- PostgreSQL 14 or newer.
- pgvector 0.8.2 for vector migrations and semantic retrieval.
- Windows x64 for the packaged Workbench candidate.
- Node.js 20+ and npm 10+ for source builds.
- LM Studio is optional for catalog/write workflows and required for semantic
  search with the documented local models.

## Known limitations

- This candidate remains unsigned while FORGE completes SignPath Foundation
  onboarding. Windows will therefore identify the publisher as unknown.
- PostgreSQL and schema bootstrap remain prerequisites for the standalone
  Workbench ZIP; the guided bootstrap owns full-machine setup.
- Fast semantic top-1 quality is below the precision reranker gate; precision
  mode meets the release threshold and remains optional.
- Core Complete does not claim automatic failover, multi-node high availability
  or support for every embedding provider.

## Distribution implementation findings

| Finding | Result |
| --- | --- |
| DIST-001 — The executable bundled production dependencies without repository or third-party notices | Fixed: the packager includes `LICENSE`, `NOTICE` and fail-closed notices for 106 production packages; deterministic generation is part of `npm run check`. |
| DIST-002 — Release metadata assumed `git` was available inside the isolated Windows bootstrap | Fixed: repository metadata is preferred, `GITHUB_SHA` is the CI fallback and unavailable provenance is explicit; the clean Windows regression passes. |
| DIST-003 — The existing `v0.1.1` tag predates Core Complete and has no canonical GitHub Release object | Accepted: it is not moved or reused; this candidate advances to `v0.2.0-rc.1`. |
| DIST-004 — The packaged executable inherited Node.js product identity and version resources | Fixed: packaging stamps and verifies FORGE product, publisher, semantic RC version and official icon before any signing step. |
| DIST-005 — Rewriting PE resources after `pkg` generation corrupts snapshot offsets and prevents startup | Fixed: an isolated Node base is stamped before `pkg` injects the snapshot; the packager verifies the resulting metadata and clean-Windows acceptance proves runtime startup. |

Future signed artifacts will follow the repository

[privacy policy](../../PRIVACY.md).

## Rollback

Withdraw the affected prerelease artifacts and return users to the last
validated release. Never reverse applied database migrations with destructive
ad-hoc SQL; publish a forward corrective migration. Treat schema checksum
mismatch, cross-project visibility, persistence loss, non-loopback Workbench
binding or credential exposure as immediate rollback triggers.
