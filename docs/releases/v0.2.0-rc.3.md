# FORGE v0.2.0-rc.3

Date: 2026-08-21  
Status: unsigned release candidate for bounded tester evaluation; not a signed
general-user release.

## What changed since rc.2

- The Windows package verifies every internal SHA-256 entry before mutation.
- Workbench updates stage and swap the application transactionally, restoring
  the previous application if publication fails.
- Normal updates preserve shared JSON and CurrentUser DPAPI material without
  asking again for the PostgreSQL password.
- Connection changes and downgrades require explicit operator intent.
- Installed packages include an allowlist/value-constrained diagnostics ZIP
  exporter for safe tester evidence.
- Windows Resilience tasks use an invisible exit-code-preserving launcher; the
  PITR monitor selects the newest typed receipt correctly on PowerShell 5.1.
- A fail-closed TencentDB Core compatibility workflow is available, but the
  provider remains uncertified until a private-VPC live run passes.

There are no database migrations or breaking Gateway/MCP contract changes
between rc.2 and rc.3.

## Compatibility

- PostgreSQL 14 or newer.
- pgvector 0.8.2 for vector migrations and semantic retrieval.
- Windows x64 for the packaged Workbench candidate.
- Node.js 20+ and npm 10+ for the guided source bootstrap.
- LM Studio remains optional except for semantic search.

## Tester path

Follow [TESTING-RC.md](../TESTING-RC.md). Existing rc.2 users should perform the
documented credential-preserving update check. Testers must verify the
published SHA-256 manifest and must not attach credentials, DPAPI files,
database dumps or recovery material to issue reports.

## Known limitations

- This candidate remains unsigned while SignPath Foundation onboarding is
  pending. Windows may identify the publisher as unknown or display SmartScreen.
- PostgreSQL and the FORGE schema are prerequisites for the standalone
  Workbench ZIP; the source archive contains the guided full bootstrap.
- Automatic failover, multi-node high availability and remote multi-user
  Workbench hosting remain outside this candidate.
- Fast semantic top-1 quality remains below the precision reranker gate;
  precision mode is optional and requires its documented local model.
- TencentDB compatibility remains unverified on a live provider instance.

## Required validation before publication

- Full monorepo build/test and zero known production vulnerabilities.
- PostgreSQL 14 schema restart plus Gateway/MCP continuity.
- Clean Windows bootstrap, DPAPI Workbench startup, resume and safe rollback.
- Update from the public rc.2 ZIP with byte-identical configuration and DPAPI.
- Tag-bound source and Windows archives with matching internal and outer
  SHA-256 manifests.
- GitHub provenance attestations for both public archives.

## Pre-publication evidence

The first isolated upgrade used the actual public rc.2 Windows ZIP, verified
its pinned SHA-256, installed it and applied a locally built rc.3 candidate.
Shared configuration and DPAPI hashes remained byte-identical; diagnostics
excluded the fixture secret and uninstall preserved both files. The same gate
is part of the tag-bound release workflow and must pass again before artifacts
are attested.

## Rollback

Withdraw rc.3 and direct testers to rc.2. Preserve the database and shared user
configuration; never reverse database migrations with destructive ad-hoc SQL.
Cross-project visibility, persistence loss, mixed-version installation,
configuration/DPAPI loss, checksum mismatch, non-loopback binding or credential
exposure are immediate withdrawal triggers.
