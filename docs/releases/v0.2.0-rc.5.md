# FORGE v0.2.0-rc.5

Date: 2026-08-27
Status: candidate prepared for unsigned bounded tester evaluation; publication
requires protected CI, the exact public rc.4 upgrade gate and tag-bound release
assembly to pass.

## What changed since rc.4

- Workbench can onboard an existing repository from a bounded documentation
  allowlist and records source provenance without reading generated or
  credential-like paths.
- Checksummed `.forge-project` bundles export and import project domain state
  using atomic create or merge modes.
- Import rejects tampering, duplicate identities, unresolved references,
  decision cycles and incompatible merge collisions before writing anything.
- Portable bundles intentionally omit embeddings, executions, immutable context
  packages, events and audit history rather than fabricating operational truth.
- Disposable Windows Sandbox and local test labs provide repeatable clean-state
  Workbench feedback without changing the installed FORGE database or profile.
- Raspberry Pi 5 Model B Rev 1.1 passed the optional ARM64 technical gate on
  Debian 13, including PostgreSQL restart/reconnect, Gateway/MCP continuity and
  Workbench project portability.

There are no database migrations or breaking Gateway/MCP contract changes
between rc.4 and rc.5.

## Compatibility

- PostgreSQL 14 or newer.
- pgvector 0.8.2 for vector migrations and semantic retrieval.
- Windows x64 for the packaged Workbench candidate.
- Node.js 20+ and npm 10+ for the guided source bootstrap.
- Raspberry Pi 5 on the recorded Debian 13 configuration is verified for
  technical testing; this is not a claim for every ARM64 distribution.
- LM Studio remains optional except for semantic search.

## Tester path

Follow [TESTING-RC.md](../TESTING-RC.md). Existing rc.4 users should perform the
documented credential-preserving update check. Test project portability only
with non-critical data and never attach credentials, DPAPI files, database
dumps, recovery material or unreviewed repository contents to issue reports.

## Known limitations

- This candidate remains unsigned while SignPath Foundation onboarding is
  pending. Windows may identify the publisher as unknown or display SmartScreen.
- PostgreSQL and the FORGE schema are prerequisites for the standalone
  Workbench ZIP; the source archive contains the guided full bootstrap.
- Project interchange carries selected domain state, not a complete operational
  database clone or disaster-recovery artifact.
- Automatic failover, multi-node high availability and remote multi-user
  Workbench hosting remain outside this candidate.
- Fast semantic top-1 quality remains below the precision reranker gate;
  precision mode is optional and requires its documented local model.
- TencentDB compatibility remains unverified on a live provider instance.

## Required validation before publication

- Full monorepo build/test and zero known production vulnerabilities.
- PostgreSQL 14 schema restart plus Gateway/MCP continuity.
- Clean Windows bootstrap, DPAPI Workbench startup, resume and safe rollback.
- Update from the exact public rc.4 ZIP with byte-identical configuration and
  DPAPI preservation, redacted diagnostics and safe uninstall.
- Native PostgreSQL project portability and end-to-end Workbench HTTP acceptance.
- Recorded Raspberry Pi 5 ARM64 acceptance with no host database or secrets.
- Tag-bound source and Windows archives with matching internal and outer
  SHA-256 manifests.
- GitHub provenance attestations for both public archives.

## Rollback

Withdraw rc.5 and direct testers to rc.4. Preserve the database and shared user
configuration; never reverse database migrations with destructive ad-hoc SQL.
Cross-project visibility, non-atomic import, persistence loss, mixed-version
installation, configuration/DPAPI loss, checksum mismatch, non-loopback binding
or credential exposure are immediate withdrawal triggers.
